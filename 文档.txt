# Oblivionis Boss 遭遇战 文档

## 需求描述
实现一个Boss+4子Boss的复合遭遇战，包含C位机制、多阶段转换、隐藏Boss。

## 敌人一览

| 敌人 | HP | 定位 | 命名空间 |
|------|-----|------|----------|
| Oblivionis | 600 | Boss，C位机制宿主 | STS2_Tomorin_Mod.Enemy |
| Doloris | 200 | 子Boss，默认C位，抽牌对策 | STS2_Tomorin_Mod.Enemy |
| Mortis | 200 | 子Boss，伤害类型对策 | STS2_Tomorin_Mod.Enemy |
| Timoris | 200 | 子Boss，单段高伤对策 | STS2_Tomorin_Mod.Enemy |
| Amoris | 200 | 子Boss，多段伤害对策 | STS2_Tomorin_Mod.Enemy |
| FullPowerOblivionis | 1000 | 隐藏Boss（独立敌人） | STS2_Tomorin_Mod.Enemy |

## 核心机制

### C位系统
- 非C位敌人获得Intangible（游戏内置Power），C位移除Intangible
- 玩家通过打出PositionZero状态卡切换C位
- C位切换时调用SetMoveImmediate切换敌人的C位/非C位行为状态（两个自循环MoveState）
- C位死亡按Doloris→Mortis→Timoris→Amoris→Oblivionis顺序自动切换

### HP削减与击杀Buff
- 每击杀一个子Boss，Oblivionis最大HP-150
- 击杀后所有玩家获得对应的永久Buff Power

### 阶段转换
| 条件 | 结果 |
|------|------|
| Boss死亡 + 0子Boss死 | 隐藏Boss（创建FullPowerOblivionis） |
| Boss死亡 + 1-3子Boss死 | 二阶段（HP+500回满） |
| 4子Boss全死 | 二阶段（HP=500回满） |

需求：

## 2026-06-26 Oblivionis enemy-turn revive fix

Requirement:
- Fix the case where Oblivionis dies during its own enemy-turn attack, for example from player Thorns after Mortis is killed, then remains at 0 HP and unattackable while rolling phase-2 moves.

Implementation notes:
- `Scripts/Enemy/Oblivionis.cs`: `WaitRelive` is marked `MustPerformOnceBeforeTransitioning = true`, so the revive move cannot be skipped by the next `RollMove`.
- `Scripts/Powers/EnemyPowers/OblivionisPowers/OblivionisHiddenRevivalPower.cs`: non-hidden paths clear `isHalfDead` and return before escaping sub-bosses. Hidden-boss handling remains limited to the 0-sub-boss-killed path.
- `Scripts/Powers/EnemyPowers/OblivionisPowers/CenterPositionManagerPower.cs`: normal Phase 2 transition now immediately escapes every living sub-boss before applying the Phase 2 passive and revive move. Hidden-boss handling is unchanged.

Manual reproduction:
- Kill Mortis to gain player Thorns, kill Amoris, switch Oblivionis to C position, leave Oblivionis at 1-5 HP with no block, then end turn and let Thorns kill it during its own attack. After the fix, Oblivionis should show and perform `Relive` before phase-2 attacks.
- For the normal player-kill path, kill any 1-3 sub-bosses, then kill Oblivionis directly on the player turn. The remaining living sub-bosses should escape immediately before Oblivionis finishes entering Phase 2.

Current phase-transition note:
- The current implementation does not auto-transition immediately when all 4 sub-bosses are killed. Phase 2 is entered when Oblivionis later dies; living sub-bosses escape during that transition, and after all 4 max-HP reductions the revive HP is based on current max HP + 500.

# Soyo Boss 假面裂痕与虚伪假面重构

Requirement:
- Refactor Soyo into a mask-task pressure phase plus true-output phase.
- The phase counter is displayed through the existing `SoyoEstrangementPower` key, but its gameplay meaning is now Mask Cracks / 假面裂痕.
- Threshold is 6. Soyo enters true phase when counter is greater than 6.
- True phase can fall back to mask only at player-turn start and only when counter is 6 or lower.
- If Soyo starts the player turn in true phase and falls back to mask, she does not auto-gain 1 counter on that same turn.
- If Soyo starts the player turn already in mask phase, counter increases by 1. If this raises counter above 6, she immediately enters true phase.
- Task success adds 2 counter and can immediately enter true phase. Task failure does not add counter.
- True phase moves keep the existing counter -2 behavior. Mask heal no longer reduces counter.

Main files:
- `Scripts/Enemy/Soyo.cs`
- `Scripts/Powers/EnemyPowers/SoyoPowers/SoyoEstrangementPower.cs`
- `Scripts/Powers/EnemyPowers/SoyoPowers/SoyoMaskedDamageReductionPower.cs`
- `Scripts/Powers/EnemyPowers/SoyoPowers/SoyoPhaseControllerPower.cs`
- `Scripts/Powers/EnemyPowers/SoyoPowers/SoyoTaskPower.cs`
- `STS2_Tomorin_Mod/localization/eng/powers.json`
- `STS2_Tomorin_Mod/localization/zhs/powers.json`
- `STS2_Tomorin_Mod/localization/eng/cards.json`
- `STS2_Tomorin_Mod/localization/zhs/cards.json`

Core APIs:
- `Soyo.EnterTruePhase()`: switches Soyo to true phase, queues the next true move, plays the first phase-change voice line once, and removes all `SoyoMaskedDamageReductionPower` stacks.
- `Soyo.EnterMaskPhase()`: switches Soyo to mask phase and queues the next mask move. It does not apply False Mask.
- `Soyo.RefreshPhaseAfterCounterChanged()`: mask-only counter refresh. If Soyo is masked and counter is above 6, she enters true phase. It does not force true phase back to mask.
- `Soyo.RefreshPhaseForPlayerTurnStart()`: player-turn-start phase logic. True phase may fall back to mask without auto-increment. Mask phase auto-increments counter by 1.
- `SoyoEstrangementPower.Modify(...)`: clamps counter at 0 and refreshes phase after modification.
- `SoyoEstrangementPower.SetAmount(...)`: sets counter to an exact clamped value and refreshes phase even if the numeric amount did not change.
- `SoyoEstrangementPower.Clear(...)`: sets counter to 0. Clearing does not force true phase back to mask outside player-turn start.
- `SoyoTaskPower.CompleteCurrentTask(...)`: if a current task exists, settles it once as success. If no task exists, it does nothing.

False Mask:
- `SoyoMaskedDamageReductionPower` is a visible buff/counter power.
- While present with positive stacks, Soyo's HP loss is multiplied by 0.25.
- At player-turn end, it loses 1 stack and is removed at 0.
- At enemy-turn start, `SoyoPhaseControllerPower` gives Soyo 1 stack if she is in mask phase.
- Entering true phase removes all False Mask stacks.
- Returning to mask at player-turn start does not immediately restore False Mask, so the next player turn after a true action can remain fully vulnerable.
- False Mask explicitly reuses the existing Soyo counter icon paths: `images/powers/SoyoEstrangementPower.png` and `images/powers/big/SoyoEstrangementPower.png`.

Task settlement:
- Success keeps the original reward and adds 2 Mask Cracks.
- Failure keeps the original penalty and does not add Mask Cracks.
- `_settled` prevents normal turn-end settlement and `CompleteCurrentTask` from resolving the same task twice.

Easter eggs:
- All Soyo easter eggs are once per combat globally.
- `PrideManSaki`: keeps voice and stun. It sets counter to 7 first, immediately refreshes phase into true, removes False Mask through true entry, then applies stun so the stun follow-up targets the true phase.
- `DoEverything`: keeps voice, 2 Weak, and 2 Vulnerable. If a task exists, completes it as success. If no task exists, it does not touch task/counter.
- `UtakotobaToken`: keeps voice and original card/buff behavior. Clears counter and removes False Mask. It does not force true phase and does not mark the next player turn as a no-mask true-action turn.

Verification expectation:

- `dotnet build`

# FeedTheCat 固定事件

## 需求描述

实现第 2 幕第一个固定事件 `FeedTheCat`。事件第一层由所有玩家投票决定全局路线，第二层仍由每名玩家独立选择具体奖励或惩罚。

## 核心规则

- 事件类名：`FeedTheCat`
- 命名空间：`STS2_Tomorin_Mod.Events`
- 固定触发：`FixedFirstEventPatch` 在 `Hook.ModifyNextEvent` 中将第 2 幕首个事件替换为 `ModelDb.Event<FeedTheCat>()`
- 随机池：不允许随机出现；`FeedTheCat.IsAllowed` 只在固定事件补丁的授权窗口内返回 true
- Shared：`IsShared => false`，保证第二层使用普通独立 `EventOption`
- 奖励路线遗物：`MatchaParfait`
- 削弱路线遗物：`EmptyParfait`
- 两个路线遗物只作标记，无战斗效果

## 第一层投票接口

文件：`Scripts/Events/FeedTheCatVoteCoordinator.cs`

- `VoteAndWaitForBranch(FeedTheCat source, FeedTheCatBranch vote)`：记录当前玩家投票并等待最终路线
- 投票 key 使用 `Player.NetId`
- host / 单人端在 `source.Owner.RunState.Players` 全员完成投票后结算，避免只根据当前已同步的事件实例子集提前决议
- 多数决决定最终路线
- 平票时使用发起事件实例的 `source.Rng.NextBool()` 随机一次
- host 使用 `PlayerChoiceSynchronizer.SyncLocalChoice(..., PlayerChoiceResult.FromIndex(...))` 广播最终路线
- client 使用 `WaitForRemoteChoice` 等待 host 结果
- 最终分支按 `Player.NetId` 找回对应 `FeedTheCat` 事件实例并应用
- 收到最终路线前不得发放 `MatchaParfait` 或 `EmptyParfait`

## 第二层选项

奖励路线：
- 先获得 `MatchaParfait`
- 回复 20% 最大生命值，始终可选
- 删除一张牌，无可删除牌时锁定
- 强化一张牌，无可强化牌时锁定

削弱路线：
- 先获得 `EmptyParfait`
- 失去 200 金币，金币不足 200 时锁定
- 获得原生 `MegaCrit.Sts2.Core.Models.Cards.Debt`

# Raana Boss 本体

## 需求描述

实现 Raana Boss 本体与相关 Power。范围只包含 Boss 本体、兴趣值 Counter、不调、兴致渐起、S3 塞 `LeftoverBuffet`、本地化与测试；不新增 `RaanaBoss` encounter，不改 Act Boss 注册，不做 bossEvent。

## 文件清单

- `Scripts/Enemy/Raana.cs`
- `Scripts/Powers/EnemyPowers/RaanaPowers/RaanaInterestPower.cs`
- `Scripts/Powers/EnemyPowers/RaanaPowers/RaanaUnwellPower.cs`
- `Scripts/Powers/EnemyPowers/RaanaPowers/RaanaRisingMoodPower.cs`
- `STS2_Tomorin_Mod/localization/eng/monsters.json`
- `STS2_Tomorin_Mod/localization/zhs/monsters.json`
- `STS2_Tomorin_Mod/localization/eng/powers.json`
- `STS2_Tomorin_Mod/localization/zhs/powers.json`
- `tests/RaanaBossBehavior.Tests.ps1`

当前 `Raana.CustomVisualPath` 暂时复用 `soyo_boss.tscn`。本任务范围不新增 Godot 视觉资源；后续接入 Encounter 或 Raana 专属视觉资源时，应替换为 Raana 专属 enemy scene。

## 入场路线

- 任意玩家拥有 `EmptyParfait`：进入强化状态，获得 `RaanaRisingMoodPower`，首行动为 S1。
- 否则任意玩家拥有 `MatchaParfait`：进入削弱状态，获得 18 格挡，首行动为 Sleep。
- 否则默认强化状态。
- 优先级固定为 `EmptyParfait > MatchaParfait > 无遗物`。

## 状态机

- 强化路线：`S1 -> S2 -> S3 -> S4_LOW/S4_MID/S4_HIGH -> S1`
- 削弱路线：`Sleep -> S1 -> S2 -> S3 -> S4_LOW/S4_MID/S4_HIGH -> S1`
- S4 三分支是三个独立 `MoveState`，用于 intent 预览和兴趣值变化后的实时刷新。

## 接口说明

- `Raana.ResolveInterestMoveState()`：根据当前 `RaanaInterestPower.Amount` 和多人阈值返回 S4 低/中/高兴趣状态。没有兴趣 Power 时按 0 兴趣处理。
- `Raana.RefreshInterestMoveStateIfNeeded()`：当当前预告处于 S4 三分支之一时，立即按最新兴趣值 `SetMoveImmediate` 到对应 S4 状态。S4 结算清零期间由 `_isResolvingS4` 防止回退到低兴趣。
- `Raana.IsCurrentInterestPreviewState()`：判断当前预告是否为 S4 三分支。
- `RaanaInterestPower.ModifyInterest(PlayerChoiceContext choiceContext, int delta, CardModel? source)`：兴趣值唯一修改入口，钳制最低 0，刷新显示并通知 Raana 更新 S4 预告。
- `RaanaInterestPower.ClearInterest(PlayerChoiceContext choiceContext)`：S4 行动结算后清零兴趣值。
- `RaanaUnwellPower`：`PowerType.Debuff` / `PowerStackType.Counter`。当 `dealer == Owner` 时 `ModifyDamageMultiplicative` 返回 `0.75m`；持有者 side 回合结束时减少 1 层，0 层移除。
- `RaanaRisingMoodPower`：`PowerType.Buff` / `PowerStackType.Single`。敌方回合结束时，如果 Raana 存活，获得 1 层 `StrengthPower`。

## 行动数值

- Sleep：不攻击；使下一次 S1 行动开始前应用 4 层 `RaanaUnwellPower`。
- S1：全体玩家 18/21 伤害。
- S2：全体玩家 5/6 x4 伤害，Raana 获得 25 格挡。
- S3：清除普通 debuff，跳过 `RaanaUnwellPower`；每移除 1 种 debuff 回复 8 HP；每名存活玩家获得 2 张 `LeftoverBuffet` 到手牌；根据当前兴趣设置 S4。
- S4_LOW：兴趣 `< 18 * playerCount`，全体玩家 28/32 伤害，所有存活玩家 2 虚弱。
- S4_MID：兴趣 `18 * playerCount <= interest < 30 * playerCount`，全体玩家 28/32 伤害，所有存活玩家 2 易伤。
- S4_HIGH：兴趣 `>= 30 * playerCount`，全体玩家 10/11 x3 伤害，Raana 获得 1 力量。
- 所有 S4 行动结算后清零兴趣并回到 S1。

# 先古之民·舞台的长颈鹿

# Stage（舞台）条件式第四层

## 需求描述

新增 Glory 后方的隐藏候选最终层 `Stage`。新 Run 只有在非每日挑战且玩家列表至少包含一名 Tomorin 时注册候选；真正转入 Stage 还要求本 Run 已真实击败 `FullPowerOblivionis`，并由同一名玩家完整持有四件指定乐器遗物。旧存档不补注册、不重排章节、不重建地图。

## 固定路线与内容接口

- `StageRouteDefinition.Nodes` 是路线顺序、地图点类型和房间类型的唯一语义来源。
- `StageActMap` 创建无分支路线并登记正式起点。
- `StageRoomResolver.TryResolveCurrentRoom` 固定解析 `GiraffeAncient`、两次 `FeedTheCat`、原版 `MechaKnightElite` 与 `CrychicPhatomBoss`；Shop 和 RestSite 保留原版实现。
- `Stage` 集中代理 Glory 临时章节资源，每项复用均带有 Stage 资源 TODO，后续替换时不需改动路线逻辑。

## 注册、进度与资格接口

- `StageRegistrationPolicy.ShouldRegister`：判断非 Daily 与任意 Tomorin 的基础注册资格。
- `StageRegistrationPolicy.RegisterAfterGlory`：按稳定模型 ID 去重，在 Glory 紧后插入 mutable Stage，保持其他自定义层的相对顺序。
- `StageRunProgressModifier`：普通 `ModifierModel`；使用 `[SavedProperty]` 保存本 Run FPO 进度、当前 Boss 奖励状态、Encounter ID、章节索引和地图坐标。
- `StageEligibility.IsEligible`：在 Glory 奖励结束后的统一转层点检查候选顺序、游戏模式、Tomorin、FPO 进度和同一玩家遗物集合覆盖。

## 奖励与转层

- `StageFpoProgressPatch` 接入 `Hook.AfterDeath`，显式拒绝 `wasRemovalPrevented`，首次记录时输出中文成功日志。
- `StageBossRewardLifecyclePatch` 只维护当前战斗资格与防重；`StageBossRewardEligibilityPatch` 在 `RewardsSet.WithRewardsFromRoom` 放行合格 FPO Boss 的原版奖励，或返回原版空终端奖励集。实现不创建固定奖励内容。
- `StageActTransitionPatch` 在多人准备同步完成后拦截 `RunManager.EnterNextAct`。资格成立时走原版下一层；不成立或候选异常时执行当前版本原版末章使用的 Architect 终局步骤。没有 Stage 的旧存档保持原流程。

## 验证约束

- 本地 xUnit 项目位于 `local-tests/Stage.Tests/`，由 `.gitignore` 精确排除；测试比较状态、集合和完整语义路线，不断言坐标、奖励或配置数值。
- 仓库静态检查为 `tests/Stage.Tests.ps1` 与更新后的 `tests/GiraffeAncient.Tests.ps1`。
- 自动化构建与测试通过后，仍需在当前游戏部署版本中完成单人、多人、存读档、奖励界面重入及跨 Mod 章节顺序的实机验收。

# BandMemberEncounter（乐队精英房）

## 需求与范围

实现一个可由代码显式实例化、但暂不进入任何 Act 遭遇池的 `RoomType.Elite` Encounter。它从当前 Run 已遇到的原始 `Anon`、`Taki`、`Soyo`、`Raana` Boss 历史中，确定性选择两个不同成员，分别放在玩家左侧和右侧，并复用游戏原生夹击语义。房间使用标准精英奖励，不追加 Boss 专属或自定义奖励。

## 核心接口

- `BandMemberKind`：四名成员的稳定代码身份。
- `BandMemberSelection.Left`／`Right`：不可重复的左右成员选择结果。
- `BandMemberSelector.FixedOrder`：只读固定候选顺序。
- `BandMemberSelector.StableNames`：只读稳定存档名映射。
- `BandMemberSelector.Select(IEnumerable<BandMemberKind>?)`：先取未遇成员，不足时从未入选成员补足；空输入按空历史处理。
- `BandMemberSelector.GetStableName(...)`／`TryParseStableName(...)`：精确、区分大小写的稳定字符串转换；拒绝未知字符串和枚举数字文本。
- `EliteStatScaler.ScaleDown(int, decimal)`：使用十进制倍率向下取整并检查非法输入与溢出；异常信息包含调用上下文。
- `BandMemberEncounter`：创建两个成员模型、读写自定义状态、读取当前 Run 历史，并在战斗开始时初始化夹击 Power。
- `BandSurroundedCoordinator.Initialize(...)`：幂等应用原生 `SurroundedPower` 与左右背击 Power。
- `BandSurroundedCoordinator.RefreshAfterEscape(...)`：敌人逃跑且仍有可攻击敌人时，通过原生 `SurroundedPower.AfterDeath(...)` 更新玩家方向。

## 模型与存档约束

- `AnonElite`、`TakiElite`、`SoyoElite`、`RaanaElite` 继承原 Boss，并继续显示原 Boss 标题。
- Elite 生命和基础攻击从原 Boss 同名虚属性经统一缩放器派生；Taki 的阶段容量一并派生。不得复制原 Boss 状态机或硬编码最终派生值。
- `AnonElite` 与 `TakiElite` 关闭原 Boss 专属奖励；`TakiElite` 逃跑时不单独结束仍有其他敌人的房间。
- Encounter 使用自定义状态键 `leftMember`、`rightMember`。只有两键都能解析且成员不同才接受恢复；否则丢弃整组状态并根据历史重算。
- 历史通过公开的 `RunManager.Instance.DebugOnlyGetState()` 获取，并遍历 `MapPointHistory[*].Rooms` 的 Encounter 与 Monster 模型 ID；Elite ID 不计入已遇成员。
- 没有合法 RunState 时按空历史确定性选择并记录一次警告，避免调试或直接实例化崩溃。

## 场景、本地化与出现范围

- 场景：`STS2_Tomorin_Mod/scenes/encounters/band_member_encounter.tscn`，包含左右两个相对槽位并居中玩家。
- 本地化：`STS2_TOMORIN_MOD-BAND_MEMBER_ENCOUNTER.title`，中文“乐队”，英文“Band”。
- `IsValidForAct` 始终返回 `false`；正式出现条件、概率、同局唯一性、专属背景与专属音乐均为后续范围。

## 验证约束与结果

- `tests/BandMemberEncounter.Tests.ps1` 覆盖全部已遇成员子集、存档名严格解析、属性派生关系、奖励边界、夹击协调、相对站位和本地化。
- 自动测试不对生命、伤害、倍率具体值、场景坐标或其他固定配置数值作断言，只验证关系、集合和行为结构。
- 仓库全部 PowerShell 回归测试已通过；`dotnet build --no-restore` 与 `dotnet publish --no-restore` 均为零错误，包含新场景的 `.pck` 已生成。
- 仍需游戏内验证单人／多人布局、死亡和逃跑换向、保存恢复、重连、标准精英奖励以及原 Boss 行为回归。

# Card List Intent（敌人卡牌列表意图）

## 需求与范围

以设计文档 `docs/2026-08-29-card-intent-tomorin-test-enemy-logic-design.md` 完全替换测试敌人的旧基础攻防牌和旧 Snapshot 语义。新逻辑包含固定 Tomorin 测试牌组、三个行动指标、双软锁、作词与重放、素材完整预留、收藏品队列、能力钩子、深度优先执行、纯数值投影及当前格式的主机权威重连状态。显式测试 Encounter 继续不进入正常 Act；正式 Boss、正式平衡、UI 扩展和实际网络传输不在本任务范围。

## 核心接口

- `EnemyCardId`／`EnemyCardDeckId`：格式为 `STS2_TOMORIN_MOD:NAME` 的稳定身份，支持严格解析。
- `EnemyCardDefinition`／`EnemyCardInstanceKey`：不可变定义与稳定战斗实例身份；定义指纹覆盖牌面、Tag、评分、素材、生命周期、作词结果和有序效果程序。
- `EnemyCardCombatState`：牌组、当前、保留、弃牌和消耗五牌区以及收藏品库存的唯一写入口；通过 `BeginExecution()`、`CompleteExecution()`、`MarkFault()` 管理运行阶段。
- `EnemyActionMetricPlanner.Prepare(...)`：选择不连续行动指标，按左到右槽位抽取、按需回洗并执行候选事务；提交时冻结保留前缀、逐来源重放上限、素材绑定、随机结果和软锁诊断。
- `EnemyCardMaterialResolver.TryReserve(...)`：按三套显式优先级生成完整、有序、无副作用的素材预留；不足时不产生部分支付。
- `EnemyCollectionInventory`：维护可用／已消耗队列，提供追加、消耗、回收、事务克隆、快照和原子应用。
- `EnemyCardExecutionEngine.ExecutePreparedActionAsync(...)`：只消费冻结行动，按深度优先步骤执行；正常素材不足截断不记 Fault，结构异常停止且不回滚已经提交的效果。
- `EnemyActionProjectionService.Project(...)`：在不推进 RNG、不执行 Hook、不改牌区的前提下计算逐牌、逐重放、逐目标预期值；未知第三方修正以不完整诊断表示。
- `CardIntentMoveState.Create(...)`：注入统一状态、规划器、执行器和游戏命令 seam；保留旧 UI 所需只读投影，不再分散持有牌区。
- `BaseCardIntentMonsterModel.CaptureReconnectState(...)`／`TryApplyReconnectState(...)`：捕获或原子应用 `EnemyCardRuntimeSyncState`。
- `EnemyCollectionInventoryPower.SynchronizeAsync(...)`：同步收藏品数量与队列描述；零库存保留 Power，仅压缩连续同类项。
- `CardIntentTestEncounter.ExplicitEncounterId`：测试房间或开发启动器可使用的稳定显式入口；`IsValidForAct` 始终为 `false`。

## 生命周期、冻结与重连语义

准备阶段把行动结构、素材候选和随机结果冻结。较早来源可消费后续 Current 牌；后续普通来源因此跳过，Inspiration 则作为受控直接执行立即结算且不再次作为计划来源。重放每次执行前消费一份已经冻结的素材绑定，首次不足或中途耗尽均正常截断，`ReplayCount` 只影响未来准备，不改写已经公开的尝试上限。保留前缀返回 Retained；普通成功牌进入弃牌，Exhaust 进入消耗区，生命周期失败按定义去向处理。

`EnemyCardRuntimeSyncState` 保存五牌区身份与顺序、ReplayCount、收藏品可用／已消耗区、冻结行动、素材绑定、随机结果、软锁诊断、运行阶段和安全步骤游标。恢复拒绝旧版本、重复身份、未知定义、非法区域或悬空引用，并只在临时状态全量验证成功后替换当前状态。捕获要求即时步骤栈为空；该 API 支持主机权威传输层接入，但当前没有网络消息补丁或普通存档迁移分支。

## 测试约束与验证结果

- `tests/CardIntentHarness/` 覆盖定义身份、规划、素材、收藏品、目录、执行、纯投影和重连原子性；36 项测试全部通过。
- `tests/CardIntent.Tests.ps1` 检查核心契约、旧类型移除、冻结计划、Power 本地化、隔离 Encounter 和 Harness；通过。
- 测试从定义、规则和输入推导预期，只比较关系、集合、身份、顺序、幂等性和状态转换，不断言固定平衡数值。
- `dotnet build` 与 `dotnet publish` 均为 0 错误，Power 本地化已经打入资源包。
- 仍需游戏内验证复合 UI、不同分辨率、死亡／离场、多人逐目标表现和真实断线重连。当前自动化验证 DTO 与原子恢复语义，不宣称已经验证网络传输。

# Card List Intent UI 修订（逐牌 Intent 与 Hover）

## 需求与范围

按 `docs/2026-08-29-card-list-intent-ui-revision-design.md` 和对应实施计划，把固定五槽、卡牌无 Hover、聚合攻击预告改为右锚固定的动态逐牌视图。每张公开牌显示自己的原版 Intent 节点，攻击数值由客户端针对本地玩家实时计算；冻结行动结构、牌区、RNG 和重连状态保持主机权威。投影异常必须保留已知结果并给出诊断和 Unknown，不得把 UI 或本地数值写回战斗状态。

## 冻结、执行与同步接口

- `PreparedEnemyCardUnitPlan`：一次成功重放的不可变执行单元，携带 `RootSourceKey`、`ExecutingCardKey`、`ExecutingCardId`、`ReplayIndex`、执行模式、素材预留和有序步骤。
- `PreparedEnemyResolutionStep`：直接效果、消费卡牌、消费收藏品、生成收藏品、作词结果、即时卡牌和回收结果七种显式步骤；即时／回收／作词子牌通过首单元和 `AdditionalReplayUnits` 表达全部连续重放。
- `EnemyPreparedResolutionPlanner.PlanSource(...)`：在候选事务副本上冻结完整 DFS 计划；即时抽牌与回收选择只在此处推进 RNG，并把虚拟作词增层计入后续 `ReplayCount`。
- `EnemyCardExecutionEngine.ExecutePreparedActionAsync(...)`：只消费冻结身份、定义、区域和预计序号，不接受随机源推进即时路径；每个安全原子边界提交 `StepPath`。
- `EnemyCardRuntimeSyncState`：schema v2 递归传输 Unit／Step DTO；恢复先在临时状态验证旧版本、步骤类型、引用、生成序号、递归预算和游标路径，全部成功后才原子替换。
- `EnemyCollectionEffectResolver.GetRequired(...)`：规划、执行与投影共享收藏品直接效果及特殊结算语义，避免三套分支漂移。

## 投影、展示与 UI 接口

- `EnemyActionProjectionService.Project(...)`：纯遍历冻结 DFS 单元，输出 `LiveActionProjection`；记录根来源、实际执行牌、重放、逐目标基础／投影命中、格挡、Power、收藏品和生成牌结果。未知修改器或结构问题返回 `IsComplete == false` 与诊断。
- `EnemyCardIntentPresentationBuilder.Build(...)`：保持公开 `CardList` 顺序和实例键，按 `RootSourceKey` 把所有子牌效果归入根牌；固定生成 Attack、Defend、Buff、Debuff、Unknown 类别。攻击只用首目标计数并验证其他目标基础命中结构。
- `EnemyCardDescriptionPresenter.BuildOverrideText(...)`：空字符串返回 `null`，表示保留原版描述；非空可信 BBCode 包裹 `[center]` 后由视图在 `NCard.UpdateVisuals` 之后写入。
- `NCardListIntentView`：用 `Dictionary<EnemyCardInstanceKey, NEnemyIntentCardSlot>` 做 keyed reconciliation；`RightAnchor` 固定，`CardRow` 随公开卡列向左增长；投影不完整时保留已知槽位并显示全局 Unknown。
- `NEnemyIntentCardSlot`：每牌维护缩略 `NCard`、效果行和原版 Single／Multi／Defend／Buff／Debuff／Unknown 节点；防御沿用原版无数值表现。
- `NEnemyCardHoverPreview`：全视图唯一共享池化预览；`_Process` 使用全局鼠标位置和完整 Canvas 变换命中缩略／预览区域，`MouseFilter.Ignore` 保证输入穿透。
- Power 刷新：视图订阅 owner 与本地玩家的 `PowerApplied`、`PowerIncreased`、`PowerDecreased`、`PowerRemoved`，通过绑定世代号合并到下一帧，只重建攻击显示。
- `NIntentCardListPatch`：普通 Intent、空列、Faulted 或视图根失败均回退原版 Unknown；投影不完整不隐藏已知逐牌内容。
